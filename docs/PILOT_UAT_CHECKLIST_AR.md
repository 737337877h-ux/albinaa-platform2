# قائمة اختبار التشغيل التجريبي الميداني

> الإصدار المرشح: **ALRAQi ERP 1.3.11** (`versionCode 15`)
> الخادم: `1.3.0-clean-test`
> البيئة: `docker-compose.clean.yml` وقاعدة `albinaa_clean`
> المدة المقترحة: 3–5 أيام، بمحصّلين اثنين ومجموعة حسابات محددة.

## قواعد التجربة

- لا تُحذف حركات مالية؛ يستخدم العكس الموثق عند الحاجة.
- كل محصّل يستخدم حسابه الشخصي ولا يشارك كلمة المرور.
- تسجّل كل ملاحظة برقم المستخدم، الهاتف، الوقت، الشاشة والخطوات.
- أي فرق مالي غير مفسر يوقف التوسع حتى تتم معالجته.
- لا تضاف ميزات جديدة أثناء التجربة؛ يسمح بإصلاح الأعطال فقط.

## 1. تهيئة المستخدمين والإسناد

- [ ] إنشاء/اختيار محصّلين اثنين وربط كل مستخدم بسجل المحصّل الصحيح.
- [ ] إسناد مجموعة صغيرة ومعلومة من العملاء والسلف لكل محصّل.
- [ ] التحقق أن المحصّل يرى المسند إليه فقط.
- [ ] التحقق أن المدير والمحاسب ومدير المديونية يرون اسم المحصّل المسند.
- [ ] التحقق من صلاحيات مستخدم القراءة فقط ومنع الإنشاء والتعديل.

## 2. الاتصال والدخول

- [ ] فتح `http://192.168.1.5:18002/health` من الهاتف على شبكة ND300O.
- [ ] تسجيل الدخول المتصل لأول مرة ومزامنة البيانات.
- [ ] إغلاق التطبيق بالكامل ثم فتح البيانات المحفوظة.
- [ ] إعادة تشغيل الهاتف ثم فتح البيانات المحفوظة والبصمة.
- [ ] تبديل المستخدم والخادم دون إغلاق التطبيق.
- [ ] التحقق من عدم اختلاط بيانات مستخدمين على الهاتف نفسه.

## 3. العمل دون اتصال

- [ ] فصل Wi‑Fi وبيانات الهاتف.
- [ ] إنشاء متابعة بنتيجة غير «تم السداد» وتحديد الموعد القادم.
- [ ] إنشاء وعد سداد.
- [ ] تسجيل تحصيل تجريبي مصرح به فقط.
- [ ] تعديل رقم العميل وإضافة رقم ثانٍ من دفتر الهاتف.
- [ ] تحديد موقع العميل وحفظه.
- [ ] إكمال مهمة والتحقق من اختفائها من القائمة الحالية.
- [ ] إغلاق التطبيق وإعادة تشغيل الهاتف والتأكد من بقاء العمليات.
- [ ] إعادة الشبكة وتشغيل المزامنة والتحقق أن العمليات انتقلت مرة واحدة فقط.

## 4. التواصل والموقع

- [ ] الاتصال بالرقم الأساسي والرقم الإضافي.
- [ ] فتح SMS وWhatsApp بقالب قابل للتعديل.
- [ ] حفظ العميل في جهات الاتصال واختيار رقم من دفتر الهاتف.
- [ ] فتح موقع العميل في الخرائط وتعديل العلامة.
- [ ] التحقق من تنبيه المزامنة عند الوصول إلى موقع العمل.

## 5. المهام والمتابعات والتحصيل

- [ ] البحث في المهام بالاسم والكود والهاتف.
- [ ] فتح إجراء من صفحة العميل والتأكد من اختيار العميل تلقائيًا.
- [ ] تعريب نوع المهمة وسبب الأولوية والإشعار بالكامل.
- [ ] نتيجة «تم السداد» لا تنشئ موعد متابعة جديدًا.
- [ ] النتائج الأخرى تتطلب تاريخ متابعة قادمًا وتقبله بالإدخال الذكي.
- [ ] التحصيل يغيّر الرصيد التشغيلي فورًا ويظهر في الويب بعد المزامنة.
- [ ] إعادة إرسال المزامنة لا تنشئ تحصيلًا أو متابعة مكررة.
- [ ] طلب تغيير الإسناد يصل للمخوّلين ويُعتمد أو يُرفض مع السبب.

## 6. المطابقة اليومية

- [ ] تعبئة [نموذج المطابقة اليومية](./PILOT_DAILY_RECONCILIATION_AR.md).
- [ ] مقارنة أرصدة العملاء حسب العملة، مع فصل السلف.
- [ ] مقارنة عدد وقيمة التحصيلات حسب الحالة والمحصّل والفرع.
- [ ] مراجعة العمليات بانتظار الإرسال وتحتاج مراجعة على كل هاتف.
- [ ] مراجعة المهام المنجزة والجديدة ومواعيد المتابعة القادمة.
- [ ] مراجعة طلبات تغيير الإسناد والإشعارات غير المقروءة.

## 7. معايير النجاح

- [ ] لا فقد أو تكرار في التحصيلات أو المتابعات أو الوعود.
- [ ] الفارق المالي صفر، أو مفسر بسجل واضح ومعتمد.
- [ ] العمل دون اتصال مستمر بعد إغلاق التطبيق وإعادة تشغيل الهاتف.
- [ ] كل محصّل يرى المسند إليه فقط.
- [ ] لا خطأ حرج أو انهيار أو انتظار يمنع المهمة الأساسية.
- [ ] موافقة مالك المنتج على الانتقال إلى مجموعة مستخدمين أكبر.
