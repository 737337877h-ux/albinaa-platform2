- بعد الانتقال إلى شبكة المكتب TP-Link_D37D نجحت النسخة القديمة محليًا، لكن فحص العنوان العام تسلسليًا استهلك نحو أربع ثوانٍ قبل اختيار الاتصال المحلي. استغرق المسار حتى تحديث الصلاحيات نحو 9.5 ثانية.

## الإصلاح

- يفحص التطبيق المسارين المعتمدين بالتوازي ويختار أول مسار سليم. لا يضيف خادمًا جديدًا، ولا يحول خادم قبول/تطوير صريحًا إلى الإنتاج، ويحترم «المحلية فقط». لا يمكن لنتيجة متأخرة تغيير المسار الفائز أو تجاوز تغيير إعدادات الخادم.
- بروتوكول اختياري بإصدار 2 وبصمات مستقلة لأقسام البيانات والأدلة. تُحسب البصمات من البيانات الجديدة المقيدة بالمؤسسة والمستخدم والصلاحيات ونوع التطبيق. يُرسل القسم كاملًا عند تغيّره، بما فيه القائمة الفارغة لإزالة السجلات القديمة؛ القسم غير المرسل يبقى محفوظًا.
- تُحفظ البيانات وبصماتها ورمز المزامنة داخل معاملة SQLite واحدة. فشل الحفظ لا يقدّم البصمات. تُرفض لقطة جزئية إذا تغير أساسها بسبب مزامنة متزامنة، ثم تُعاد قراءة اللقطة مرة واحدة دون إعادة إرسال العمليات المالية.
- تستمر إعادة تركيب العمليات المحلية المعلقة بعد تطبيق اللقطة. تظل مبالغ الكسور كما هي، مع فحص الهوية وقفل الجلسة ومفاتيح العمليات الأصلية.
- يعود العميل إلى العقد القديم عند رجوع الخادم إلى نسخة لا تقبل حقل البصمات. لا يعيد الطلب عند خطأ تحقق آخر، ولا يعيد تشغيل كتابة مالية.
- حُدد انتظار نبضة حالة الجهاز بثلاث ثوانٍ، مع تسجيل أزمنة المراحل دون كلمات مرور أو رموز جلسات أو بيانات العملاء. أصبح خطأ الاتصال واضحًا بالعربية.
